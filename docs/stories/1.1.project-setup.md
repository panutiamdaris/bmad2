### Project Structure and Organization
**[Source: architecture/09-source-tree.md]**

The monorepo structure follows this exact organization:
```
vehicle-tracker/
 .github/workflows/     # GitHub Actions CI/CD
 packages/
  web/                  # Next.js 14.1.0 frontend with App Directory
   src/app/
   public/
   tests/
  sync-engine/          # Client-side sync logic (Dexie.js wrapper)
   src/
  api/                  # Azure Functions 4.x for main API
   src/functions/
   tests/
  sync-worker/          # Azure Functions for background sync processing
   src/functions/
  shared/               # Shared TypeScript types, schemas, utilities
   src/
    types/
    schemas/
    constants/
    utils/
  infrastructure/       # Azure Bicep IaC files
   main.bicep
   modules/
   parameters/
 scripts/               # Build and deployment automation
 docs/                  # Project documentation
 turbo.json            # Turborepo configuration
 pnpm-workspace.yaml   # pnpm workspace definition
 package.json          # Root package with workspace config
 tsconfig.json         # Base TypeScript configuration
```

**Key Package Dependencies:**
- web → shared, sync-engine
- sync-engine → shared
- api → shared
- sync-worker → shared
- shared → none (no dependencies on other packages)

### Coding Standards to Apply
**[Source: architecture/12-coding-standards.md]**

**File Naming:**
- All files use kebab-case: `sync-manager.ts`, `vehicle-card.tsx`
- React components: PascalCase for component, kebab-case for file: `VehicleCard` in `vehicle-card.tsx`

**TypeScript Configuration:**
- Strict mode MANDATORY
- No `any` type usage (prefer `unknown` + type guards)
- Explicit return types on public functions
- Use `interface` for object shapes
- Use `readonly` for immutable props

**ESLint & Prettier:**
- Single quotes
- 2-space indentation
- 100 character line width
- Trailing commas in multi-line
- No semicolons (Prettier default)

**Constants:**
- Use SCREAMING_SNAKE_CASE for constants: `MAX_RETRIES`, `API_BASE_URL`

**Error Handling:**
- Never use console.log in production
- All async functions must have try/catch blocks
- Use error code constants (no hardcoded error strings)

**Security:**
- No secrets in code (use environment variables)
- Add .env files to .gitignore
- Validate all inputs with Zod schemas

3. **Lint Test:** Verify ESLint and Prettier run without errors
4. **TypeScript Compilation Test:** Verify strict mode TypeScript compiles across all packages
5. **Script Execution Test:** Verify all npm scripts execute without errors
